# Project Authorizations

Purpose: record durable project-level authorizations so future work does not depend on chat memory.

## Standing authorizations from Bernd

- Maintain and extend the Project Memory system.
- Create implementation branches and pull requests for project-memory governance changes.
- Update documentation, ledgers, open loops, dependencies, evidence, decisions and handoff files when needed.
- Treat WellFit-now as the technical web/backend repository, not the visual design repository and not the native AR/Buddy repository.

## Not covered by standing authorization

These still require live capability, credentials, platform confirmation or explicit confirmation when requested by the tool/platform:

- revealing, rotating or creating production secrets;
- destructive infrastructure actions;
- production database writes or restores;
- billing/payment changes;
- publishing production releases;
- bypassing failing security or governance checks;
- granting third-party account permissions.

## Operating rule

If a requested action is already covered here and technically possible through connected tools, proceed without asking again. If the platform requires confirmation or the action is outside this file, stop and mark the blocker in project-memory/OPEN_LOOPS.md or project-memory/SESSION_HANDOFF.md.
